# 客户服务申请系统 - 项目结构与部署说明（给部署同事）

> 本文档供负责部署的同事快速理解系统架构、文件结构和部署方式。
> 详细操作手册见 `deploy/DEPLOY.md`。

---

## 一、系统是什么

客户服务申请系统：客户在公网提交服务申请（重置密码/改域名等 9 种），系统自动完成：
**提交 → 邮件中转 → 域名校验 → 服务商身份验证 → 售后通知** 的完整闭环。

关键设计：**前端与后端不直接通信，数据通过"中转邮箱"以标准格式邮件传递**（邮件驱动架构）。

---

## 二、整体架构

```
┌─────────────── 公网服务器 A ───────────────┐
│  Nginx :80/443 (HTTPS)                     │
│    ├─ /        → 前端表单页（客户用）        │
│    └─ /api/*   → relay :3003 (反代)         │
│  relay 容器 :3003（发信中继，无状态零存储）  │
└───────────────┬────────────────────────────┘
                │ SMTP（发到中转邮箱）
                ▼
          cz@coremail.cc（中转邮箱，自发自收）
                ▲
                │ IMAP（后端拉取）
┌───────────────┴────────────────────────────┐
│  公司内网服务器 B (Docker)                  │
│  ├─ mysql:8（客户/代理商/申请数据）          │
│  └─ backend 容器 :3002                     │
│       ├─ 入站监控（拉 cz 中转邮箱）          │
│       ├─ 回件监控（400cz 邮箱收发）          │
│       └─ 管理后台（内网访问）               │
└────────────────────────────────────────────┘
```

**安全边界**：公网只暴露前端页 + relay（仅能发信到中转邮箱）；客户名单、代理商、附件全部在内网。

## 三、邮件流转流程

```
① 客户公网提交 → relay 打包标准邮件 → 发到 cz@coremail.cc（中转）
② 内网后端每 30s 拉取中转邮箱 → 白名单/格式校验 → 入库
③ 域名匹配客户库 → 400cz 发验证邮件给服务商
④ 服务商回复 → 400cz 收到 → 线程关联 → 确认/拒绝判定
⑤ 确认 → 通知售后(support@coremail.cn)；拒绝 → 通知客户
```

**三个邮箱角色**：
| 邮箱 | 角色 |
|------|------|
| cz@coremail.cc | 中转：前端 → 后端数据通道（自发自收）|
| 400cz@icoremail.cn | 对外收发：发服务商、收服务商回复、（兜底邮箱）|
| support@coremail.cn | 售后通知收件人 |

## 五、部署概要

### 前置
- 公网服务器 A + 内网服务器 B，均需 Docker + Compose
- 域名（如 apply.company.com）解析到 A
- 中转邮箱 cz@coremail.cc、400cz@icoremail.cn 凭证

### 内网 B（后端 + 数据库）
```bash
cd /opt/cz/deploy
cp .env.example .env     # 填 DB_PASS / SMTP / IMAP / INBOUND 等
docker compose -f compose.internal.yml up -d --build
# 首次部署需迁移数据（mysqldump + uploads），见 DEPLOY.md 6.2
```

### 公网 A（前端 + relay）
```bash
cd /opt/cz/deploy
cp .env.example .env     # 填 RELAY_*（cz 中转邮箱发信凭证）
docker compose -f compose.public.yml up -d --build
certbot --nginx -d apply.company.com   # HTTPS
```

### 关键配置提醒
- 内网 B：`ALLOWED_ORIGINS` 需含公网域名（https://apply.company.com）
- 公网 A：`RELAY_ALLOWED_ORIGINS` 需含公网域名
- 密码含特殊字符（如 `$Abc@123&x,:`）必须单引号包裹
- 缺失环境变量后端/relay 启动会报错并列出缺失项（这是特性，不是 bug）
